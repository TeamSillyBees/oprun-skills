# Qveris 接入验收（2026-11-18）

客户端：QVeris Studio 1.0.22，macOS。使用客户端可见界面与系统辅助功能；无 CDP 入口。未读取认证存储，未修改 OpRun 业务服务，未查询项目或执行业务写入。

## 已核实

- 原一句话安装入口失败：Qveris 的 web_fetch 明确返回“此地址未返回可读取的网页或文本：application/octet-stream”。首轮包含 17 次工具请求、4 次失败，随后人工停止；不是安装成功。
- Release 资产 MIME 元数据可设置为 text/plain，但实际下载仍可能被 GitHub 强制返回 application/octet-stream。因此入口必须使用 GitHub 网页版 INSTALL.md，包下载工具另走固定正式标签。
- 新会话默认只启用 QVeris MCP；已有 OpRun 连接未自动在会话中启用。启用后，客户端真实执行一次 oprun_account_context，工具轨迹显示已返回，回答显示调用成功。
- 原保存目录为 31 个工具。用户完成原生“保存并授权”的登录授权后，客户端显示“已验证连接，发现 43 个工具”，包括文件上传、工序执行及结算工具。
- 再次点击“验证并刷新”，客户端显示“连接验证成功，工具列表已更新”，保持 43/43 个工具。没有删除连接、扩大配置中的 Scope 或清空其他设置。
- 技能库搜索 oprun 无结果：MCP 已连接不等于 Skill 已安装。客户端提供“添加技能 → 上传 ZIP／上传技能文件夹”。
- v1.3.1 九项发布资产下载后与本地构建字节一致；33 项本地安装、更新、同步、打包、发布验证通过。

## 后续真实复测

- 用户通过原生“上传 ZIP”完成导入，界面显示“技能已导入，可在对话输入框的技能菜单中选择使用”，已安装数量从 41 增至 42。新会话已选中 oprun-project-planning。
- 用户导入的 v1.3.1 ZIP 与 v1.3.2 ZIP 字节完全一致；本次是安装指引与发布工具更新，Skill 内容未变，无需再次覆盖。
- 在加载 Skill 并启用现有 OpRun 连接的会话中，发送网页入口的一句话更新请求。共 3 次请求、102.8 秒，无失败：读取公开网页、查看连接器工具、oprun_account_context。三条实际工具回执均显示“已返回”，重连后的只读调用通过。
- 客户端明确报告“更新未执行”，原因是当前研究会话没有执行下载程序或替换本地 Skill 的能力；它没有反复重试、重建连接或冒充更新成功。当前 Qveris 的实际安装/更新需要原生 ZIP 导入，一句话只完成引导与连接检查。
- 现有 OAuth 范围保持不变；工具目录包含新能力不代表连接已授权该能力。文件、执行、验收、放行、资金及结算仍按实际 scope_missing 提示按需重新授权。

## 验收边界

- 通过：原生安装及会话加载、网页指引读取、用户登录授权回跳、43 项工具加载、原生刷新重连、重连后真实只读调用；遇到宿主无安装能力时明确降级。
- 不宣称通过：一句话在 Qveris 内自动替换 Skill 文件。当前宿主未提供该能力，不通过修改业务服务或读取客户端私有认证存储绕过。
- 仍未实测：不同 Skill 内容版本的原生覆盖更新、客户端重启后的恢复、Token 自然到期刷新。此次 ZIP 内容相同，不能当作不同内容的升级验证。

安装指引要求：先检查宿主工具与当前会话连接；缺少下载/写文件/命令执行能力时直接使用原生导入，不反复搜索研究工具。工具缺失与未授权、Skill 缺失分别处理。任何业务权限仍以账号上下文与实际服务端判断为准。
