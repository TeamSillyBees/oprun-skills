# 更新与兼容

以服务器 `oprun://integration/manifest` 资源、`tools/list` 和实际授权为准。清单列出业务契约、Skill 文件摘要、SDK 和不可变 UI 版本。文件摘要只能确认完整性，不能替代对发布者的信任。

1. 已安装 ZIP / 插件不一定随服务器自动更新。比较清单版本后，使用该宿主的原生更新或重新加载流程；只在不兼容时提示用户更新，不反复要求重新授权。
2. `resources/read` 读取 Skill 不等于宿主激活 Skill。仅双方明确支持 Skills 扩展时才使用远程加载；其他客户端继续使用标准 Skill 包。
3. MCP Apps 支持情况按客户端、版本、账户功能和实测记录区分。不要把模型名称或 `clientInfo` 当作权限或页面支持证据。
4. 兼容更新不扩大授权、不清除设置，也不重发业务写入。新范围仍需用户确认。网页备选使用普通登录，链接不携带访问凭据。
5. 旧 UI 资源保留原构建；服务器可返回兼容投影或安全网页查看入口。新会话可发现新版本，运行中的页面不强制切换。
6. 联网检查失败表示“更新情况未知”，不是“已是最新”。官方版本、本地锁定版本、实测版本和线上版本是四件不同的事。

全流程扩展见[文件与工序操作](workflow.md)。接入前核对实际服务端能力；本地 Skill 更新不表示这些工具已上线。旧连接需要用户重新授权新增 scope，不能自动扩大原授权。

## 独立服务与统一连接

Skill 唯一维护源是 `TeamSillyBees/oprun-mcp` 的 `skills/oprun-project-planning`；`oprun-skills` 仅分发固定提交的校验副本。安装或更新时核对分发清单的 `mcp_revision`、Skill 文件摘要及服务器 `oprun://integration/manifest`；不能把本地新包当作线上已支持。

继续使用同一 `/mcp` 地址与 OAuth 连接，方案、发单、接单和交付无需分别配置。先读 `oprun_account_context`，依据当前主体和 `allowed/reason/required_scopes` 选择能力。换身份不等于提升权限，旧授权不会自动增加 scope。

服务重启、回滚或网络失败后，保留原任务、上传、操作编号与 request_key。先查询状态，再继续原操作；只有明确失败且用户确有新意图时才准备新操作。服务不可用时提供普通网页登录入口，不改成无鉴权请求。
